# AI Iteration Guide: nuxt-ai-i18n

This document provides a comprehensive overview of the `nuxt-ai-i18n` project, designed to help future AI agents or developers understand the architecture, implementation details, and roadmap for further iterations.

## 1. Project Vision
**"AI-First, Human-Verified"**
A Nuxt 3 internationalization workflow where developers write in their native language (Chinese), and AI handles the rest (extraction, translation, and UI for human correction).

### 2.2 Data Flow
1. **Extraction**: Developers use `$t('中文')` or `<AiI18nT tKey="中文" />`.
2. **Detection**: Runtime plugin checks if the key exists in the current locale's dictionary.
3. **AI Translation**: If missing, a POST request is sent to `/api/ai-i18n/translate`.
4. **Persistence**: Translated content is saved to `locales/[lang].json`.
5. **Visual Feedback**: AI-generated content is marked with a yellow dashed border in "Edit Mode".
6. **Human Correction**: Users click the text, edit in the overlay, and save back to the server.

## 3. Implementation Details

### 3.1 The `tKey` vs `key` Conflict
In Vue, `key` is a reserved attribute. To avoid rendering issues and SSR hydration mismatches, the `AiI18nT` component uses `tKey` as its primary prop.
- **Correct**: `<AiI18nT tKey="你好" />`
- **Incorrect**: `<AiI18nT key="你好" />`

### 3.2 SSR & Hydration
The plugin uses `useState` to sync the dictionary between server and client. Visual Editor is wrapped in `<ClientOnly>` to prevent server-side DOM access errors.

### 3.3 Visual Editor Mechanism
- **Global Listener**: Uses a captured click event listener on `window` to intercept clicks on elements with `data-i18n-key`.
- **Status Highlighting**: CSS classes (`ai-i18n-ai-generated`, `ai-i18n-human-reviewed`) are applied based on metadata in the dictionary.
