# nuxt-ai-i18n

> **Build-time AI-powered internationalization for Nuxt 3.**
> Write Chinese (or any source language) directly in your code. Run one CLI command. Ship fully translated apps — with zero runtime overhead.

---

## Why nuxt-ai-i18n?

Traditional i18n workflows are painful:

| Pain Point | Traditional i18n | nuxt-ai-i18n |
|---|---|---|
| Key management | Manually maintain `en.json`, `ja.json`… | Auto-extracted from source code |
| Translation | Copy-paste into spreadsheets / Crowdin | `npx ai-i18n sync` — done |
| Review | No visual context | Click any text in the browser to edit |
| Runtime cost | Lazy-load locale files | Pre-generated JSON, zero API calls at runtime |
| AI integration | Not applicable | First-class: works with Cursor, Claude Code, etc. |

---

## Architecture: Build-time AI

```
┌─────────────────────────────────────────────────────────────────┐
│                        DEVELOPMENT TIME                         │
│                                                                 │
│  1. Write code with Chinese source text                         │
│     $t('用户仪表盘')  or  <AiI18nT tKey="用户仪表盘" />          │
│                                                                 │
│  2. Run CLI (once, or on every save in Cursor/Claude Code)      │
│     OPENAI_API_KEY=sk-... npx ai-i18n sync                      │
│                                                                 │
│  3. CLI scans .vue/.ts files → extracts keys → calls LLM       │
│     → writes locales/en.json, locales/ja.json, locales/ko.json  │
│                                                                 │
│  4. Visual Editor: open browser, click text, fix translations   │
│     → saves back to locales/*.json                              │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                          RUNTIME                                │
│                                                                 │
│  • Nuxt serves pre-generated locales/*.json via API             │
│  • Plugin loads locale JSON on language switch                  │
│  • No LLM calls, no latency, no API key needed in production    │
└─────────────────────────────────────────────────────────────────┘
```

## Quick Start

### 1. Install

```bash
pnpm add nuxt-ai-i18n
```

### 2. Configure

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['nuxt-ai-i18n'],
  aiI18n: {
    defaultLocale: 'zh',          // Source language
    locales: ['en', 'ja', 'ko'],  // Target languages
  },
})
```

### 3. Use in your components

```vue
<template>
  <!-- Component style -->
  <AiI18nT tKey="欢迎使用" />

  <!-- Function style -->
  <p>{{ $t('用户仪表盘') }}</p>

  <!-- Dynamic keys -->
  <AiI18nT :tKey="dynamicKey" />
</template>
```

### 4. Generate translations (dev/build time)

```bash
# Set your API key once
export OPENAI_API_KEY=sk-...

# Scan project and translate all missing keys
npx ai-i18n sync

# Options:
npx ai-i18n sync --locales en,ja,ko,fr,de
npx ai-i18n sync --model gpt-4.1-mini
npx ai-i18n sync --force          # Re-translate everything
npx ai-i18n sync --output-dir i18n/locales

# List all source keys found in the project
npx ai-i18n list
```

### 5. Visual proofreading

1. Run your Nuxt dev server: `pnpm dev`
2. Click **"进入编辑模式"** in the top-right corner
3. Click any text on the page to open the inline editor
4. Save — changes are written to `locales/*.json` immediately

## CLI Reference

```
ai-i18n sync [options]

Options:
  -p, --path <path>          Root path to scan (default: cwd)
  -l, --locales <locales>    Comma-separated target locales (default: en,ja,ko)
  -s, --source-lang <lang>   Source language code (default: zh)
  -o, --output-dir <dir>     Output directory for locale JSONs (default: locales)
  -m, --model <model>        OpenAI model (default: gpt-4.1-mini)
  --force                    Re-translate all keys, even if already translated
```

## Runtime API

### `$t(key: string): string`

Translates a key using the current locale's pre-generated dictionary.

```ts
const { $t } = useNuxtApp()
const label = $t('用户仪表盘') // → "User Dashboard" (in English)
```

### `$setLocale(locale: string): Promise<void>`

Switches the active locale and loads its dictionary.

```ts
const { $setLocale } = useNuxtApp()
await $setLocale('en')
```

### `$locale: Ref<string>`

Reactive reference to the current locale.

### `$editMode: Ref<boolean>`

Toggle the Visual Editor overlay.

## Cursor / Claude Code Integration

Add this to your `.cursorrules` or `CLAUDE.md`:

```markdown
After adding or modifying any Chinese UI text, run:
  OPENAI_API_KEY=<key> npx ai-i18n sync
to keep all locale files up to date.
```

Or add a `package.json` script:

```json
{
  "scripts": {
    "i18n:sync": "ai-i18n sync",
    "i18n:list": "ai-i18n list"
  }
}
```

## Locale File Format

Locale files use a simple flat JSON format with the source key as the key:

```json
{
  "用户仪表盘": "User Dashboard",
  "今日访问量": "Today's Visits",
  "已完成": "Completed"
}
```

This makes them easy to version-control, diff, and manually edit.
